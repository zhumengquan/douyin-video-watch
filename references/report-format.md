# 观感报告格式

给 agent 看抖音内容时，输出按这个结构写。目的是让读报告的人能分辨：
**哪些是创作者说的、哪些是我看见的、哪些是我没看到的。**

## 视频作品

```
## <标题>

**作者** · **时长** · **类型**（视频/图文）
<简介原文，保留话题标签>

### 画面里发生了什么

| 时间 | 画面 |
|------|------|
| 00:00 | 封面：大字标题「XXX」压在画面上，主体是…… |
| 00:02 | …… |
| 00:06 | 出现数据面板，三根柱状图分别为 0.44 / 0.41 / 0.32 |

### 口头/文字信息

从标题、简介、以及画面上的文字里能提取到的：

- 主题：……
- 关键数据：……（注明来源是标题还是画面）
- 提到的人物/产品/工具：……

### 我的判断

<这里写理解，不是复述。比如这套内容的表达结构、信息密度、面向谁>

### 没看到的

- 抽帧覆盖 X 个时间点，不等于看完整段
- 音频内容未转写（如果有 ASR 才写这部分）
- 画面上 X 区域被遮挡/看不清
```

## 图文作品

图文没有时间轴，按图序写：

```
## <标题>

**作者** · **N 张图**
<简介原文>

### 逐图内容

| # | 图里的内容 |
|---|------------|
| 1 | 封面：…… |
| 2 | …… |

### 核心信息
……
```

## 几条硬规则

**1. 分清"说的"和"看到的"**

创作者在标题里写了「平均差异约 0.01–0.02 m/s」，这是**他说的**，不是我验证的。
画面里我看到三根柱状图是 0.44 / 0.41 / 0.32，这是**我看到的**。
两者要分开写，不能混成一句「数据显示差异很小」。

**2. 简介和画面冲突时，两个都写出来，不要替它圆场**

实测踩到：抓举视频简介写「188kg」，判分牌上写的是「184 kg」。
还有一次简介详细描述了"速度曲线、杠铃轨迹"这些叠加层，
但抽出的帧里一帧都没有。

这种时候：
- 两个数字并列写，标清各自来源
- 写"不确定哪个对"
- **不要自己选一个更合理的**，也不要写"应该是笔误"

**3. 时间戳必须真实**

时间戳来自 `frames.json`，不要估。名字里的时间是抽帧时的实际时间点。

**3.5 联系表上读到的数字不算读，必须回原帧确认**

这条单独列出来，因为它害我写错过两次。

实测：看 1200px 联系表（每格 300px）时，我把判分牌的"一白一红两个灯"
读成了"两个白灯"；把标签「上挺峰值速度 (m/s)」读成了"平均速度 1.45"。
放大到原帧（720×1280）才发现两处都错。

**规则：**
- 联系表只用来判断"哪一帧值得细看"
- **任何数字、文字、颜色、指示灯、图表刻度，都回原帧看**
- 写进报告前问自己：这个数我在画面哪个位置看到的？完整标签是什么？

**读错不可怕，读错了还写得很确定才可怕。**

**4. 不确定就说不确定**

- 画面糊、字太小 → 写"看不清"
- 只抽了 10 帧，中间隔了 8 秒 → 写"这 8 秒内画面如何变化未知"
- 没做音频转写 → 写"音频内容未获取"

**5. 不要编造画面外的内容**

抖音的标题经常很夸张（"教科书般的深蹲"），**别把这个当画面描述**。
画面里就是一个人在蹲，就写一个人在蹲，蹲了多少重量看画面上的字。

**6. 抽帧数量有限，别当成完整观看**

10 帧覆盖 23 秒，平均每 2.3 秒一个采样点。
如果内容是快剪或信息密集（比如密集出现数据面板），主动提示"可能漏掉了中间状态"。

**7. "我没看到"≠"画面里没有"，怀疑漏帧就先补测**

这是最容易犯也最贵的错误。实测：发现抽出的帧里没有"举起"的画面，
就断定是抽帧算法漏了快速动作，动手改了算法默认参数。
后来用 20fps 把那段时间窗逐帧抽出来看，才发现**画面上本来就没有那个动作**
（机位太远，主体太小）。

正确顺序是：
1. 报告里写"这几秒没覆盖到"
2. 如果这段是理解内容的关键，**用高帧率补测那个时间窗**（`ffmpeg -ss` 逐帧抽）
3. 补测完再判断是"漏帧"还是"画面本来没内容"
4. 确认是算法问题时才改算法

**8. 联系表里自己认出重复帧**

`outro: true` 的帧已经被脚本排除了。但仍可能有两种重复漏进来：
- 片头/片尾的同一张数据卡（机器认不出，见 SKILL.md 已知局限二）
- 同一动作的不同瞬间（这是正常的，是动作的相位）

判断标准：**如果是"同一张信息卡的两种排版"，跳过一个；
如果是"同一个动作的不同阶段"，留着。**

---

## 附：技术记录段（可选）

如果这次抽帧过程有值得记的东西（补测、参数调整、异常），
在报告末尾加一小节，把**做了什么、看到了什么**写清楚。
读者据此能判断这份报告的观察边界在哪。
